## Overview

In this tutorial, you build a controller that answers `GET /health` with a JSON body. `@antelopejs/interface-api` declares HTTP routes, reads request data, and returns responses from TypeScript controllers. The same interface also declares WebSocket handlers.

The package holds the contract and the decorators. It is not an HTTP server. Your controllers run inside an AntelopeJS module, and a module that implements the interface, such as `@antelopejs/api`, serves them. Configure the servers of that implementation before you call `Listen()`.

The examples use TypeScript's legacy decorators (`experimentalDecorators: true`). Keep the AntelopeJS compiler configuration that your module already has. Standard JavaScript decorators do not support these parameter decorators.

The interface has three parts:

- A controller groups routes under a shared base path. Controllers nest.
- A route decorator (`@Get`, `@Post`, `@Put`, `@Delete`) maps a method to an HTTP endpoint. The prefix, postfix, and monitor decorators add hooks around it.
- A parameter decorator (`@Parameter`, `@JSONBody`, `@RawBody`, `@Context`, and others) injects request data into a handler argument.

## Installation

Add the interface to your module:

```bash
pnpm add @antelopejs/interface-api
```

## Add your first route

Write the controller in a file that your module imports, so that its decorator runs. The example declares `GET /health`. It does not start a server or configure a port.

```ts docs-check
import { Controller, Get } from "@antelopejs/interface-api";

class HealthController extends Controller("/health") {
  @Get("")
  status() {
    return { healthy: true };
  }
}
```

The route path is empty on purpose. `@Get()` with no argument uses the method name and registers `/health/status`. After the implementation starts listening, request `/health` on its configured address. You see the JSON body `{ "healthy": true }`.
