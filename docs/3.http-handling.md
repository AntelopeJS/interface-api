A handler returns a plain value for an ordinary response. `HTTPResult` sets a status code, headers, or a stream. `RequestContext` gives the underlying Node.js request and response.

## The `HTTPResult` class

`HTTPResult` is an HTTP response. It holds the status code, the body, the content type, custom headers, and an optional stream. The constructor is `new HTTPResult(status = 200, body?, type?)`.

### Basic usage

A route handler returns a plain value or an `HTTPResult`. `@antelopejs/api` wraps a plain value in an `HTTPResult` with status 200.

```typescript
import { Controller, Get, Post, HTTPResult } from "@antelopejs/interface-api";

class ExampleController extends Controller("/examples") {
  @Get()
  getExample() {
    // Returns JSON (content-type: application/json)
    return { status: "success", data: [1, 2, 3] };
  }

  @Get("text")
  getTextExample() {
    // Returns plain text (content-type: text/plain)
    return "This is a text response";
  }

  @Get("custom")
  getCustom() {
    // Returns a fully customized response
    const result = new HTTPResult(200, "<h1>Hello World</h1>", "text/html");
    result.addHeader("X-Custom-Header", "Custom Value");
    return result;
  }
}
```

### Status codes

Set the status code with the constructor or with `setStatus(status)`. `getStatus()` returns it.

```typescript
import { HTTPResult } from "@antelopejs/interface-api";

// Through the constructor
const notFound = new HTTPResult(404, "Not Found");

// Through setStatus
const forbidden = new HTTPResult();
forbidden.setStatus(403);
```

### Response body

The body is an `HTTPBody`:

```ts
type HTTPBody =
  | string
  | number
  | boolean
  | null
  | readonly HTTPBody[]
  | { readonly [key: string]: HTTPBody | undefined }
  | { toJSON(): HTTPBody };
```

The third constructor argument, or the second argument of `setBody(body, type?)`, sets the content type.

```typescript
import { HTTPResult } from "@antelopejs/interface-api";

// String body (text/plain)
const textResult = new HTTPResult(200, "Hello World");

// Object body (application/json)
const jsonResult = new HTTPResult(200, { message: "Success" });

// Custom content type
const htmlResult = new HTTPResult(200, "<p>HTML content</p>", "text/html");
```

A string body is sent as is, with the content type `text/plain`. Any other body goes through `JSON.stringify`, with the content type `application/json`. A value with a `toJSON` method, such as a `Date` or a `Buffer`, is written through that method. An omitted body is the empty string. `getBody()` returns the body text as a string, and `getContentType()` returns the content type.

The object member of `HTTPBody` has a string index signature. A value typed by an `interface` has no index signature, so TypeScript accepts it only once you spread it (`{ ...value }`) or type it with a type alias.

### Custom headers

`addHeader(name, value)`, `removeHeader(name)`, `getHeaders()`, and `peekHeaders()` manage the custom response headers.

```typescript
import { HTTPResult } from "@antelopejs/interface-api";

const result = new HTTPResult(200, "Success");

// Add headers
result.addHeader("X-Rate-Limit", "100");
result.addHeader("X-Rate-Limit-Remaining", "99");

// Remove a header
result.removeHeader("X-Rate-Limit");

// Get all headers
const headers = result.getHeaders();

// Read headers without creating the mutable store
const existingHeaders = result.peekHeaders();
```

### The `withHeaders` static method

`HTTPResult.withHeaders(res, headers, defaultStatus = 200)` wraps a plain body in a new response. If `res` is an `HTTPResult`, it adds the headers to that same object and returns it, without a copy. `defaultStatus` sets the status only for a new response.

```typescript
import { HTTPResult } from "@antelopejs/interface-api";

// From a plain body
const result = HTTPResult.withHeaders(
  { message: "Success" },
  { "X-Request-Id": "abc-123" },
);

// From an existing HTTPResult
const original = new HTTPResult(200, { data: "test" });
const withExtra = HTTPResult.withHeaders(original, {
  "Cache-Control": "no-cache",
});
// withExtra === original; original now has the extra header.
```

### Streaming responses

For long-running processes or server-sent events, `getWriteStream()` puts the response in stream mode and returns its `PassThrough` stream. `isStream()` reports whether the response is in stream mode.

```typescript
import {
  Controller,
  Get,
  Context,
  WriteStream,
  RequestContext,
} from "@antelopejs/interface-api";
import { PassThrough } from "node:stream";

class StreamController extends Controller("/stream") {
  @Get()
  async streamData(
    @Context() context: RequestContext,
    @WriteStream() stream: PassThrough,
  ) {
    stream.write("Starting stream\n");

    for (let i = 0; i < 10; i++) {
      await new Promise((resolve) => setTimeout(resolve, 1000));
      stream.write(`Data chunk ${i}\n`);
    }

    stream.end("Stream complete\n");
    return context.response;
  }
}
```

`getWriteStream(type = "text/plain", status = 200)` takes an optional content type and an optional status code.

## The `RequestContext` interface

`RequestContext` holds the request data that a handler can read.

| Property          | Type                        | Description                                                                             |
| ----------------- | --------------------------- | --------------------------------------------------------------------------------------- |
| `rawRequest`      | `IncomingMessage`           | The raw Node.js HTTP request object                                                     |
| `rawResponse`     | `ServerResponse`            | The raw Node.js HTTP response object                                                    |
| `url`             | `URL`                       | The parsed request URL                                                                  |
| `routeParameters` | `Record<string, string>`    | Parameters extracted from URL path segments                                             |
| `body`            | `Promise<Buffer>`, optional | The pending body read that `ReadBody` stores. Undefined until a handler reads the body. |
| `response`        | `HTTPResult`                | The response object sent to the client                                                  |
| `error`           | `unknown`, optional         | Error thrown during processing, if any                                                  |
| `connection`      | `unknown`, optional         | WebSocket connection of the implementation, for a WebSocket handler                     |

## Read request bodies

`ReadBody(context, limit?)` reads the raw request body and returns a `Promise<Buffer>`. `@RawBody()` injects the same buffer. The default limit is `DEFAULT_REQUEST_BODY_LIMIT`, 1 MiB. If the `Content-Length` header or the received data exceeds the limit, the read rejects with an `HTTPResult` of status 413 and the body `Payload Too Large`.

```typescript
import { Controller, Post, RawBody } from "@antelopejs/interface-api";

class UserController extends Controller("/users") {
  @Post()
  async createUser(@RawBody() body: Buffer) {
    const data = JSON.parse(body.toString());
    return { id: "new-user", ...data };
  }
}
```

For a JSON body, use `@JSONBody`. It checks the JSON syntax, not the shape of the value. A TypeScript annotation does not check request data either, so validate the value before you read its fields, for example with [API Util](https://interfaces.antelopejs.com/docs/api-util/introduction). An empty body produces `undefined`.

```typescript
import { Controller, Post, JSONBody } from "@antelopejs/interface-api";

class UserController extends Controller("/users") {
  @Post()
  async createUser(@JSONBody() userData: { name: string; email: string }) {
    return { id: "new-user-id", ...userData };
  }
}
```

To accept a larger buffered body on one endpoint, pass a limit in bytes to `@RawBody`, `@JSONBody`, or `ReadBody`:

```typescript
import { Controller, Post, RawBody } from "@antelopejs/interface-api";

const TEN_MIBIBYTES = 10 * 1024 * 1024;

class UploadController extends Controller("/uploads") {
  @Post()
  async upload(@RawBody(TEN_MIBIBYTES) body: Buffer) {
    return { bytes: body.length };
  }
}
```

For a body that should not sit in memory, such as a file upload, read it as a stream with `@BodyStream()` or `StreamBody(context)`. No limit applies, so the handler bounds what it accepts. If the loop stops early, the rest of the body is discarded and the client still gets the response. Read a body once, either as a stream or with `ReadBody`.

```typescript
import { createWriteStream } from "node:fs";
import { Readable } from "node:stream";
import { pipeline } from "node:stream/promises";
import {
  BodyStream,
  Controller,
  HTTPResult,
  Put,
} from "@antelopejs/interface-api";

class FilesController extends Controller("/files") {
  @Put("/:name")
  async upload(@BodyStream() body: AsyncIterable<Uint8Array>) {
    await pipeline(Readable.from(body), createWriteStream("/tmp/upload"));
    return new HTTPResult(200, { success: true });
  }
}
```

## Cross-origin requests

`GetCorsConfig()` returns the current `CorsConfig`. `SetCorsConfig(config)` replaces it for the next requests without a server restart. Both functions return promises and need an API implementation.

```ts docs-check
import { GetCorsConfig, SetCorsConfig } from "@antelopejs/interface-api";

await SetCorsConfig({
  allowedOrigins: [
    "https://app.example.com",
    /^https:\/\/preview-\d+\.example\.com$/,
  ],
  allowedMethods: ["GET", "POST"],
  allowedHeaders: ["Content-Type", "x-antelopejs-auth"],
  credentials: true,
  maxAge: 600,
});

// Preserve other settings when changing one field.
const current = await GetCorsConfig();
await SetCorsConfig({ ...current, maxAge: 300 });
```

| Property         | Type            | Meaning                                                                                          |
| ---------------- | --------------- | ------------------------------------------------------------------------------------------------ |
| `allowedOrigins` | `AllowedOrigin` | A string, a `RegExp`, or an array of either. Omitting it disables CORS.                          |
| `allowedMethods` | `string[]`      | Allowed cross-origin HTTP methods.                                                               |
| `allowedHeaders` | `string[]`      | Allowed request headers. If omitted, the implementation reflects the client's requested headers. |
| `credentials`    | `boolean`       | Whether to send `Access-Control-Allow-Credentials`.                                              |
| `maxAge`         | `number`        | Preflight cache lifetime in seconds.                                                             |

All fields are optional. For credentialed requests, list the trusted origins. CORS controls browser access to responses. It does not replace authentication or authorization.
